# v3: команда из шести агентов по исходному плану

v3 реализует состав агентов из плана проекта (разделы 6–10) и проверяет его на OULU-NPU. Код прежних экспериментов (`triage/*.py`, замороженные v2 и holdout) не изменялся; v3 живёт в `triage/team/`, `scripts/v3_*.py`, `experiments/v3_team/`.

## Агенты и инструменты

| Агент | LLM-вызовы | Инструменты (локальные) | Выход |
|---|---:|---|---|
| 1. Оркестратор | 2 (план, закрытие) | общая память SQLite (`StateStore`), очередь задач (`TaskQueue`) | план задач с фокусом для каждого анализатора; итоговый статус |
| 2. Анализ живости | 1 | MiniFASNetV2 (L1), модель магистерской работы V_june (L2), OpenCV лицо/качество (L3) | оценка live/spoof, согласие моделей, качество кадра, предполагаемый артефакт, риск |
| 3. Устройство и канал | 1 | парсер метаданных устройства и потока (C1), база сигнатур виртуальных камер/эмуляторов/hooking (C2) | признаки виртуальной камеры, эмулятора, перехвата, аномалии потока, риск канала |
| 4. Сессионный контекст | 1 | история попыток SQLite (S1), связанные учётные записи (S2), локальная таблица IP-диапазонов (S3) | частота попыток, связанные учётные записи, категория IP, риск сессии |
| 5. Верификатор | 1 (+1 после перепроверки) | валидатор схем и ссылок (V1), детерминированные правила согласованности (V2) | accept / recheck(агент, вопрос) / manual_review |
| 6. Заключение | 1 | справочник типов атак (K1), поиск похожих инцидентов в архиве (K2), запись заключения (K3) | вердикт, тип атаки, риск, уверенность, рекомендация, доказательства по агентам, противоречия, текстовый отчёт оператору |

Типовой инцидент: 7 вызовов LLM + 15 вызовов инструментов (в плане 7 + 14; у агента живости на один инструмент больше — вторая модель). Перепроверка добавляет 2 вызова LLM и 1 инструмент. Лимиты: 25 шагов и 90 с на инцидент, не более одного цикла перепроверки; при превышении — ручная проверка.

Порядок (план, раздел 7): оркестратор регистрирует инцидент в общей памяти и строит план → анализаторы 2–4 работают **параллельно** (3 слота llama.cpp) → верификатор → не более одной адресной перепроверки → агент заключения → оркестратор закрывает инцидент. Агенты обмениваются типизированными сообщениями (`Message`, Pydantic), все сообщения сохраняются в `results/<run>/state.sqlite`.

Решения, принятые по итогам отладки (только на отладочной выборке):
- Правила V2 разделены на ошибки отчётов (утверждение аналитика противоречит фактам инструмента — повод для перепроверки) и межсигнальные конфликты (например, «живое лицо + виртуальная камера» — типичный признак внедрения; передаются в заключение, а не считаются ошибкой).
- После перепроверки верификатор получает схему без варианта recheck (урок протокола v1).
- Связь «вердикт → допустимые рекомендации и типы атак» задана в грамматике декодирования (`anyOf` по вердиктам), а не только в валидаторе.
- Оркестратор при закрытии может только понизить решение до ручной проверки, но не изменить вердикт; соблюдение лимитов считает код.

## Рекомендации

`allow` — допустить; `reverify` — запросить повторную верификацию; `block_escalate` — заблокировать попытку и эскалировать; `escalate` — ручная проверка оператором. Повторная верификация допускается только при вердикте bona_fide (вероятно подлинный пользователь с недостаточными данными, например при отказе PAD или плохом качестве кадра). Атакующему повторная автоматическая попытка не предлагается. Система ничего не блокирует сама: это рекомендации оператору.

## Данные

- Кадры: локальная тестовая часть OULU-NPU (пользователи 36–55, 6 телефонов, 3 сессии, по одному кадру на видео; файлы 1 — живые, 2–3 — печать, 4–5 — повтор с экрана). Лицензия OULU-NPU не разрешает распространение: кадры и кропы в репозиторий не попадают, хранятся только относительные имена файлов, SHA-256 и выходы моделей.
- Разбиение по людям: пользователи 36–39 — отладка и архив похожих инцидентов, 40–55 — оценка. Каждый инцидент использует собственный кадр.
- Оценка: 48 инцидентов (16 bona_fide, 16 presentation_attack — 8 печать + 8 экран, 16 injection_attack), отладка 9, архив 54.
- Модель магистерской работы V_june: обучена только на LCC_FASD, OULU-NPU для неё zero-shot. Вариант и порог (0,302) выбраны по LCC development до этого эксперимента; кропы взяты из кеша её пайплайна (RetinaFace ×1,5, 128×128), воспроизведение сверено с `per_image_dump_full.json` (максимальное отличие 1e-6).
- Синтетическое: метаданные устройства и потока, сессии и история попыток (SQLite), причина пометки, сценарий внедрения (виртуальная камера, эмулятор, hooking, «скрытая» подмена без сигнатуры), контролируемые сбои и недоверенный текст. Внедрение задано генератором, реальных подмен потока нет.
- Внешние API (AbuseIPDB, геолокация) не используются по решению автора; категория IP берётся из локальной синтетической таблицы.

## Методы сравнения

- `A_minifas`, `A_thesis` — только одна PAD-модель.
- `B` — фиксированные правила над теми же инструментами.
- `C` — один LLM-агент, видит все выходы инструментов, один вызов.
- `T` — команда из шести агентов.

LLM: Qwen2.5-7B-Instruct Q4_K_M (официальный GGUF Qwen, ревизия `bb5d59e`), llama.cpp b12032 (коммит dde879bc4, тот же, что в исходных сериях) для macOS arm64, Metal, температура 0, seed 8217, JSON-schema grammar. API-стоимость 0.

## Воспроизведение

```bash
# веса PAD (сверяются по SHA-256 из report_materials/local_protocol_v2_holdout/asset_manifest.json)
# LLM: qwen2.5-7b-instruct-q4_k_m-0000{1,2}-of-00002.gguf из Qwen/Qwen2.5-7B-Instruct-GGUF@bb5d59e
.runtime/llama-b12032-macos/llama-b12032/llama-server -m models/qwen2.5-7b-instruct-q4_k_m-00001-of-00002.gguf \
  --host 127.0.0.1 --port 8080 --alias qwen2.5-7b-instruct-q4_k_m -c 24576 -np 3 -ngl 99 --seed 8217

OULU_NPU_DIR=~/Downloads/Oulu-NPU THESIS_ONNX_DIR=~/sist/analysis/finetune_onnx \
  .venv/bin/python -m scripts.v3_prepare_oulu        # уже выполнено; не перезапускать поверх замороженных данных
.venv/bin/python -m scripts.v3_run --run-id <new_debug_id> --split debug --max-seconds 90
.venv/bin/python -m scripts.v3_run --run-id <new_eval_id> --split evaluation --max-seconds 90
.venv/bin/python -m scripts.v3_report --run-id <new_eval_id>
```

Оценочный запуск возможен только при совпадении SHA-256 кода и данных с `experiments/v3_team/data/freeze.json`. Повтор с новым run_id — те же наблюдения, а не новая выборка.
